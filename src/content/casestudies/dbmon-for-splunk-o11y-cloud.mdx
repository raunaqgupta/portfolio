## The need for Database Monitoring

Splunk Observability Cloud is a Gartner leader in observability solutions with a comprehensive set of features for monitoring applications, infrastructure, and end-user monitoring. However, it lacked robust database monitoring capabilities. This gap between application performance and database performance made it challenging for users to identify and troubleshoot database-related issues affecting their applications.

Every competitive observability platform had database monitoring capabilities that extended beyond currently on offer. Customers had been asking for it on Splunk Ideas forum for years, and it was a glaring omission in Splunk Observability Cloud's feature set.

We also knew from Appdynamics's success that customers were willing to pay ~$50 million in ARR. Therefore, we set out to build a robust database monitoring solution within Splunk Observability Cloud.

### Expanding addressable user base

It was evident that Database monitoring would complement existing workflows for DevOps, and Software Reliability Engineers (SREs). But in addition to that, Database monitoring would also open up new use cases that target new personas; specifically Database Administrators (DBAs) which would effectively increase the potential market cap for Splunk Observability Cloud.

### Filling the gap

![Databases sit at the intersection of applications and infrastructure](https://r2-image.raunaqgupta.workers.dev/dbmon-for-splunk-o11y-cloud/problem.png?f=avif)

At the time, users had access to query performance metrics through APM traces. However, these metrics were limited in scope and did not provide a comprehensive view of database performance. Users needed a comprehensive view into the performance of each query that was being executed especially if it was a slow or a long-running query.

### An independently licensed vertical

Splunk Observability Cloud sold its features as independent verticals. Customers could choose to buy only the features they needed. This meant that Database monitoring had to be designed as an independent vertical with its own license, pricing, and onboarding flows. At the same time, it had to be deeply integrated with existing verticals such as Application Performance Monitoring (APM), and Infrastructure monitoring to provide a seamless user experience.

## Designing for speed (of execution)

The design process began with understanding three new aspects: how Splunk Observability Cloud was structured, how Splunk UI components and patterns worked, and the roadmap of various database monitoring features ahead of us.

### Visualizing the query explain plan

The query explain plan was visualized using a tree structure to represent the various operations involved in executing a database query. Each node in the tree represented a specific operation, such as a table scan, index scan, join, or sort. The nodes were color-coded based on their execution time, allowing users to quickly identify the most time-consuming operations.

Multiple micro-interactions were finessed with the frontend team to ensure that the tree structure was intuitive and easy to navigate.

## Key decision points

<List>
  <li>Integrating Database monitoring with existing verticals such as APM and Infrastructure monitoring.</li>
  <li>Diffrentiating between Database monitoring and Infrastructure while ensuring a seamless user experience.</li>

## Impact

On the Alpha launch of the vertical where we had 11 customer signups, we were able to convert 7 of them to paying customers within the first 3 months of launch. This was a significant achievement and demonstrated the value of the product.

## Learnings

{/* What you’d repeat, what you’d do differently, and what surprised you. */}

Building a new product vertical within an existing platform has many layers to unravel. For instance, the existence of a design system does not necessarily mean the design patterns are well-documented or even understood consistently across teams. Without a well-defined design strategy, it can be challenging to ensure consistency when launching new features.
