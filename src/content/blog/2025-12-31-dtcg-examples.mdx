DTCG (Design Tokens Community Group) has defined a design token specification in JSON syntax. The [specification](https://www.designtokens.org/tr/2025.10/) is divided into three modules: [Format](https://www.designtokens.org/tr/2025.10/format), [Color](https://www.designtokens.org/tr/2025.10/color/), and [Resolver](https://www.designtokens.org/tr/2025.10/resolver/). `Format` provides the general details, `Color` provides the syntax specifically for color tokens, and `Resolver` provides how to define multiple contexts under which the tokens can be "resolved".

Some highlights from the `Format` specification:

- There are essentially two types of entities: groups and tokens. Groups do not have a `$value` property, while tokens do.
- A token requires an unambiguous `$type` but can inherit it from its parent group.
- There are currently 7 core types: `Color`, `Cubic Bezier`, `Dimension`, `Duration`, `FontFamily`, `FontWeight`, and `Number`. All core types can only have a singular `$value`.
- Composite types are distinguished by having objects or arrays as their `$value`. Currently supported composite types are `Border`, `Gradient`, `Shadow`, `Stroke style`, `Transition`, and `Typography`.


## Example: Base colors

This example define three [color tokens](https://www.designtokens.org/tr/2025.10/color/#base).

```json
{
  "color": {
    "palette": {
      "gray": {
        "1000": {
          "$type": "color",
          "$value": {
            "colorSpace": "oklch",
            "components": [1, 0, 0],
            "alpha": 1,
            "hex": "#ffffff"
          }
        },
        "900": {
          "$type": "color",
          "$value": {
            "colorSpace": "oklch",
            "components": [0.9911, 0, 0],
            "alpha": 1,
            "hex": "#fcfcfc"
          }
        },
        "0": {
          "$type": "color",
          "$value": {
            "colorSpace": "oklch",
            "components": [0, 0, 0],
            "alpha": 1,
            "hex": "#000000"
          }
        }
      } 
    }
  }
}
```

Here, `color`, `palette`, and `gray` are all groups, while `1000`, `900`, and `0` are the actual color tokens. The numbering utilized is defined as an [ordered scale](https://www.designtokens.org/tr/2025.10/color/#ordered-scales). Each color token has a `$type` of `color` and a `$value` that defines the color in the OKLCH color space along with its hex representation.

As can be seen, `$type` is being repeated for each token even though we know that they will be colors because of their parent groups. To avoid this redundancy, DTCG allows us to define the `$type` at the group level, which will then be inherited by all child tokens. Here's how that would look:

```json
{
  "color": {
    "$type": "color",
    "palette": {
      "gray": {
        "1000": {
          "$value": {
            "colorSpace": "oklch",
            "components": [1, 0, 0],
            "alpha": 1,
            "hex": "#ffffff"
          }
        },
        "900": {
          "$value": {
            "colorSpace": "oklch",
            "components": [0.9911, 0, 0],
            "alpha": 1,
            "hex": "#fcfcfc"
          }
        },
        "0": {
          "$value": {
            "colorSpace": "oklch",
            "components": [0, 0, 0],
            "alpha": 1,
            "hex": "#000000"
          }
        }
      } 
    }
  }
}
```

Their equivalent CSS variables would end up as:

```css
:root {
  --color-palette-gray-1000: oklch(1 0 0);
  --color-palette-gray-900: oklch(0.9911 0 0);
  --color-palette-gray-0: oklch(0 0 0);
}
```
